# v2.1.0-preview.7

Windows x64向けのプレビュー版です。アプリ表示番号は `2.1.0`、MSIX番号は `2.1.0.25` です。

## preview.6からの変更

- 記録WebをWindowsアプリ経由でローカル接続できるようにしました。PC上のゲームLauncherを起動後、同じPCの `http://localhost:47832/` から記録Webにアクセスできます。PCで起動したゲーム、または稼働中にPCから記録を確定したゲームと現在の枝に追従し、記録操作や区間、本文の訂正、画像と経路を共有します（[Issue #481](https://github.com/natumekazuki/GameLauncherWithGit/issues/481)）。
- スマホやタブレットからは同じtailnet内のTailscale Serveを通して接続できます。PCで許可したゲームを選び、表示された接続コードを端末に入力します。コードは5分間・1回限り、接続許可は最長8時間です。インターネット向けのFunnelは使わず、コードと接続情報は共有しないでください。
- 自動コミットと自動プッシュの間隔を「設定」→「同期・通知」で別々に指定できます。各0〜1440分で、0は無効ではなく追加の待ち時間なしを意味します。旧設定では両方0として従来どおり動作します。「すべて同期」と「同期を再開」は間隔を待ちません。送信先を一つに特定できない場合はプッシュせず、理由を通知します。
- 関連リポジトリを設定した作品の本文・訂正・画像・区間・経路などは、リポジトリとGitブランチごとに切り替わります。新しい枝は空で、元の枝に戻るとその記録へ戻ります。抽出設定とタグ名の定義は作品共通です。MCPでは `scenario_history_scopes` で範囲を確認し、対応する `captureGameId` を指定できます。
- シナリオ画面に共有の読み込みインジケーターを統合しました。PC・Web・キャプチャの各ワークスペースで同一のローディング状態を表示し、発生画像の読込中や記録先の確認中でも一貫したフィードバックを提供します。
- 発生画像をフロー詳細と共有表示するスロットを統合しました。範囲の詳細から発生画像を選択して表示でき、選択外の要素不在と添付なしの空配列を区別します。画像読み込み失敗時は代替の読み込み状態を表示します。
- 記録履歴をリポジトリのブランチごとにスコープ分けしました。新しい枝では空の状態から始まり、元の枝に戻るとその記録へ復帰します。MCPの `scenario_history_scopes` で現在の範囲を確認できます。
- Windows設定にPCライブラリのエントリーを追加し、ゲーム一覧からの遷移を簡素化しました。「Git状態を更新」は対象リポジトリを読み直しますが、fetch・pull・コミット・プッシュは行いません。同じリポジトリを使う作品にも結果が反映されます。
- 記録の確定操作で、実際の記録先と確認済みの記録先を区別して表示します。範囲の保存メタデータ発生詳細から編集でき、選択された発生画像をフロー詳細内に表示します。
- 記録中のワークスペース状態をステータス読み込みエラーを通じて保持します。テキストと終了選択肢の優先順位を狭い画面で調整し、ローディングスピナーのキャプション表示を削除しました。

## 互換性とデータ保護

- 枝の出典がない既存の記録は、PCの「従来の記録」から参照できます。従来の作品IDはMCPでも枝の出典がない記録を指します。関連リポジトリ未設定の作品は従来どおりです。
- 記録WebはPCのプレイ対象がない間は待機します。すでに起動しているゲームはPCのシナリオ画面で「記録の準備」から接続し、「確定して記録」を押してください。テスト接続だけでは対象は切り替わりません。
- OpenTelemetry Exporterの既知の脆弱性は [Issue #21](https://github.com/natumekazuki/GameLauncherWithGit/issues/21) で継続管理しています。OTLP exporterは登録していませんが、対象DLLは残り、修正済みではありません。
- 復元時の対象外Androidワークロードのサポート終了警告と、`mspdbcmf.exe` 不在によるシンボルパッケージ未生成は継続します。

## 配布と確認状況

- MSIXの名前・発行者・署名証明書はpreview.6と同じで、番号を `2.1.0.23` から `2.1.0.25` へ増やしています。Windows x64 Releaseのビルド・署名付きMSIX発行、署名・Identity・native12ファイル・ライセンス・Web資産を確認しました。
- Windowsは自己完結.NET / ASP.NET Core runtimeとMCP依存を同梱します。配布先でASP.NET Core runtimeを別途導入する必要はありません。CoreCLR・hostpolicy・ASP.NET Core assemblies・deps/runtimeconfigの実同梱を確認しています。
- 本体・固定サブモジュール・pristineなMinHook/uchardet・ライセンス・ビルド手順を `GameLauncherWithGit-v2.1.0-preview.7-source.zip` に収録します。GitHub自動生成ZIPだけでは代用できません。ネイティブ入力はpreview.6から変更せず、公開preview.6の署名済みMSIXから同一の12ファイルを再利用しました。ソースZIPは配布準備commitのtracked本体と固定入力に対応します。短いパスへ展開してビルドしてください。
- 番号更新を含むソースでCapture 107件・MCP 9件・Git 6件のテストがRelease構成で成功しました。実ユーザーDB・キー・画像を使わず、合成データで照合・出現参照・選択境界・実ZIP・MCP transportの二権限・版/scope・場面/タグ移行・区間話者集計を確認しています。

## 未確認事項・既知の制限

- 今回のMSIXのインストール・更新インストール、実ゲームでの接続・一連の操作、runtime未導入の別PC、外部MCPクライアント製品との接続は未確認です。実ユーザーデータは操作していません。
- ネイティブWebViewでの新機能操作、通知の可視表示・音、全DPI・混在DPI・複数モニター・排他表示・他作品・長時間大量画像・同時処理の網羅は未確認です。Windows実機検証の残りは [Issue #29](https://github.com/natumekazuki/GameLauncherWithGit/issues/29) で管理しています。
- 本文取得・分類・話者照合はベストエフォートです。全作品・全文章・画面との完全一致・未取得文の復元は保証せず、OCR・翻訳は提供しません。DLL注入を行うため信頼できるゲームだけへ接続してください。画像は直近本文の近傍シーンの目印で、厳密な行同期ではありません。出力条件で本文を除外しても画像は切抜き・墨消しせず、画像内の除外本文が残る場合があります。
- 記録WebのTailscale Serve経由接続は同じtailnet内のみ有効です。Funnel（インターネット公開）は使用していません。接続コードは5分間・1回限りの有効で、8時間以内に切断されます。
- OpenTelemetry Exporter 1.14.0の既知の中程度の脆弱性警告3件は [Issue #21](https://github.com/natumekazuki/GameLauncherWithGit/issues/21) で継続管理しています。現在はファイルログのみを登録しOTLP exporterを登録していませんが、対象DLLは配布物に残り、修正済みではありません。

実装に対応する詳細は、[連続照合・観測経路・手動場面・ZIP契約](https://github.com/natumekazuki/GameLauncherWithGit/blob/385a909209391bb44c1946b09c68bd09e4dc4b04/docs/design/scenario-extraction.md)、[MCPの設定・二権限・資料版](https://github.com/natumekazuki/GameLauncherWithGit/blob/385a909209391bb44c1946b09c68bd09e4dc4b04/docs/design/scenario-mcp.md)、[Windows配布運用](https://github.com/natumekazuki/GameLauncherWithGit/blob/385a909209391bb44c1946b09c68bd09e4dc4b04/docs/design/windows-msix-keyvault-signing.md)を参照してください。
