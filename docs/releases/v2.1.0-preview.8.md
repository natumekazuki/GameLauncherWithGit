# v2.1.0-preview.8

Windows x64向けのプレビュー版です。アプリ表示番号は `2.1.0`、MSIX番号は `2.1.0.26` です。

## preview.7からの変更

- PCと記録Webの「フロー」で、その記録先の保存区間を名前で示し、観測できた区間間の流れ・分岐・合流を表示します。保存区間に属さない記録は、同じ経路で続くまとまりごとに「未設定区間」として示します。区間を選ぶと本文画面でその範囲を読め、画像は本文詳細で確認できます。本文とフローのタブ切替では同じ対象の状態を保持し、取得中や失敗は図と区別して更新操作で再試行します。この区間図は製品UI用で、MCP・ZIPの既存の本文出現単位の `graph` は変更しません。
- 記録中に本文の末尾を見ていると、PC・記録Webとも新着が保存されるたびに表示が更新され、描画後に末尾へ追従します。過去の閲覧、検索、本文の選択・編集、区間指定の間は閲覧位置を変えず、更新を保留します。通常表示で末尾までスクロールすると追従を再開し、「最新へ」でも戻れます。
- PCの本文行から、確認した1出現だけを削除できるようにしました。右クリック、フォーカスして Shift+F10、タッチの長押しで行メニューを開きます。確定時に記録ID・item ID・取得回・受信連番・元のUTF-16位置を同じ書込境界で再照合し、対象が変わっていれば削除しません。同じ受信原文から分割した他の行や、同じ文面の別の出現は残ります。記録Webには行削除を公開しません。
- 行メニューと本文の表示位置を調整しました。メニューを開いた対象行を明示し、アンカーが動いたときだけ閉じ、長押しを離しても閉じません。折り返しコントロールの下でも本文末尾が収まるようにしました。
- 区間図の表示を調整しました。選択中の区間の操作をチャートの隣に保ち、保存区間の機械IDを安定して扱い、本文のない保存区間も保持します。
- バージョンを `2.1.0.25` から `2.1.0.26` へ増やしました。

## 互換性とデータ保護

- 既存の保存区間・本文・画像・手動場面・タグはそのまま参照できます。区間図は保存済みの区間と観測済みの経路から表示用に導出し、新しい区間や本文を作りません。未設定区間は本文表示だけの指定で、既存の書き出し条件には追加しません。
- 行削除で削除したUTF-16範囲は再分割・ルール再適用の対象から除外し、同じ原文の残存itemと別の出現は維持します。同じ原文の表示itemが残る間は画像添付も維持し、最後のitemを削除したときに未参照画像を回収します。既存の原文単位の一括削除は従来どおりです。
- MCPとZIPの既存の本文出現単位の `graph`、`scenario_history_scopes`、二権限の契約は変更していません。
- OpenTelemetry Exporterの既知の脆弱性は [Issue #21](https://github.com/natumekazuki/GameLauncherWithGit/issues/21) で継続管理しています。OTLP exporterは登録していませんが、対象DLLは残り、修正済みではありません。
- 復元時の対象外Androidワークロードのサポート終了警告と、`mspdbcmf.exe` 不在によるシンボルパッケージ未生成は継続します。

## 配布と確認状況

- MSIXの名前・発行者・署名証明書はpreview.7と同じで、番号を `2.1.0.25` から `2.1.0.26` へ増やしています。Windows x64 Releaseのビルド・署名付きMSIX発行、署名・Identity・native12ファイル・ライセンス・Web資産を確認しました。
- Windowsは自己完結.NET / ASP.NET Core runtimeとMCP依存を同梱します。配布先でASP.NET Core runtimeを別途導入する必要はありません。CoreCLR・hostpolicy・ASP.NET Core assemblies・deps/runtimeconfigの実同梱を確認しています。
- 本体・固定サブモジュール・pristineなMinHook/uchardet・ライセンス・ビルド手順を `GameLauncherWithGit-v2.1.0-preview.8-source.zip` に収録します。GitHub自動生成ZIPだけでは代用できません。ネイティブ入力はpreview.7から変更せず、公開preview.7の署名済みMSIXから同一の12ファイルを再利用しました。ソースZIPは配布準備commitのtracked本体と固定入力に対応します。短いパスへ展開してビルドしてください。
- 番号更新を含むソースでCapture・MCP・Git・PlayRecordingWebのテストがRelease構成で成功しました。実ユーザーDB・キー・画像を使わず、合成データで照合・出現参照・選択境界・単一出現削除の再照合・区間図の導出と保存・実ZIP・MCP transportの二権限・版/scope・場面/タグ移行・区間話者集計を確認しています。

## 未確認事項・既知の制限

- 今回のMSIXのインストール・更新インストール、実ゲームでの接続・一連の操作、runtime未導入の別PC、外部MCPクライアント製品との接続は未確認です。実ユーザーデータは操作していません。
- ネイティブWebViewでの新機能操作、通知の可視表示・音、全DPI・混在DPI・複数モニター・排他表示・他作品・長時間大量画像・同時処理の網羅は未確認です。Windows実機検証の残りは [Issue #29](https://github.com/natumekazuki/GameLauncherWithGit/issues/29) で管理しています。
- 本文取得・分類・話者照合はベストエフォートです。全作品・全文章・画面との完全一致・未取得文の復元は保証せず、OCR・翻訳は提供しません。DLL注入を行うため信頼できるゲームだけへ接続してください。画像は直近本文の近傍シーンの目印で、厳密な行同期ではありません。出力条件で本文を除外しても画像は切抜き・墨消しせず、画像内の除外本文が残る場合があります。
- 記録WebのTailscale Serve経由接続は同じtailnet内のみ有効です。Funnel（インターネット公開）は使用していません。接続コードは5分間・1回限りの有効で、8時間以内に切断されます。
- OpenTelemetry Exporter 1.14.0の既知の中程度の脆弱性警告3件は [Issue #21](https://github.com/natumekazuki/GameLauncherWithGit/issues/21) で継続管理しています。現在はファイルログのみを登録しOTLP exporterを登録していませんが、対象DLLは配布物に残り、修正済みではありません。

実装に対応する詳細は、[連続照合・観測経路・手動場面・ZIP契約](https://github.com/natumekazuki/GameLauncherWithGit/blob/9e45f6f/docs/design/scenario-extraction.md)、[MCPの設定・二権限・資料版](https://github.com/natumekazuki/GameLauncherWithGit/blob/9e45f6f/docs/design/scenario-mcp.md)、[Windows配布運用](https://github.com/natumekazuki/GameLauncherWithGit/blob/9e45f6f/docs/design/windows-msix-keyvault-signing.md)を参照してください。
