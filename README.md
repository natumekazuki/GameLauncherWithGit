# GameLauncherWithGit

## 開発・リリース運用

### 課題と対応予定

- 不具合、機能要求、対応が必要な後追いは [GitHub Issues](https://github.com/natumekazuki/GameLauncherWithGit/issues) で管理し、重複は既存の Issue に集約する。着手順は依頼内容と影響を踏まえ、データの安全性や主要な同期動作に関わるものを優先する。
- 正式版ごとに `vX.Y.Z` の Milestone を使い、対応予定が決まった Issue を割り当てる。Milestone 未指定は対応版未定のバックログとする。追加・延期するときは対象 Issue の割り当てと理由を更新する。
- 変更は作業ブランチで進め、`main` に統合する。対応した Issue は対象の変更が `main` に反映され、必要な確認が完了してから閉じる。重複や不採用の場合は理由を残して閉じる。Issue の完了と正式公開は別であり、Milestone は対象版の公開後、未完了課題の延期または対象外を整理して閉じる。
- リリース範囲を決めるときと公開前に、対象 Milestone の未完了課題と、Milestone 未指定でも今回の変更に関連する課題を確認する。未完了の非ブロッカーは公開判断と分け、延期する理由と引継ぎ先を Issue に残す。

### 互換性とデータ保護

実際に利用中の環境では、ゲーム登録・関連リポジトリ・セーブリンクの情報を含む `game-library.db`、`settings.json`、サムネイル、ゲームのセーブデータ、関連リポジトリのデータと同期先、および適用済みのデータ移行を維持対象とする。アプリ更新後も登録情報と設定を利用でき、セーブデータや同期先を損なわないようにする。必要な移行を行う場合も、既存データとその意味を維持する。

利用・適用済みかどうかで維持対象を判断し、Git タグの有無だけでは判断しない。未配布の開発途中の仕様や画面配置そのものとの互換性は保証しないが、そこで実際に使われているデータは保護する。データの消失や利用不能を伴う変更は、メジャーバージョンを上げるだけで実施せず、影響と対応方法を示して承認を得る。

### バージョン

正式版は `X.Y.Z` 形式とし、複数の種類の変更を含む場合は影響が最も大きいものに合わせる。

- `X`（メジャー）: 既存の動作環境、利用中の機能またはデータとの互換性を壊す変更。`Y` と `Z` を `0` に戻す。
- `Y`（マイナー）: 互換性を保つ機能追加や、機能・操作性の改善（不具合修正を除く）。`Z` を `0` に戻す。
- `Z`（パッチ）: 互換性を保つ不具合修正や、機能を追加しない内部改善・依存更新・文書変更。

番号の更新対象と Windows のビルド・MSIX 確認は、[バージョン更新チェックリスト](docs/design/windows-msix-keyvault-signing.md#7-バージョン更新チェックリスト)に従う。

### 正式公開

1. 公開範囲を決め、作業ブランチで対象版の番号を更新する。`docs/releases/vX.Y.Z.md` に変更内容、互換性への影響、実施した検証と未確認事項を記録する。詳細文書やソースへのリンクは、その版の内容に対応するコミットの完全ハッシュで固定する。
2. 公開対象の変更を `main` に統合し、対象コミットで必要なビルド・動作確認を行う。MSIX を配布する場合は配布用パッケージも確認する。確認結果が記録と異なれば公開前に記録を更新し、最終的な公開対象に確認結果が適用されることを確かめる。
3. 公開対象の `main` のコミットに `vX.Y.Z` タグを付け、同じタグを指定して GitHub Release を作成する。公開済みタグは移動・削除しない。同名タグのローカルとリモートが食い違う場合は強制更新せず、原因と対応を確認する。

方針の定義は、Issue や Milestone の更新、push、統合、タグ操作、公開の実行許可を代替しない。

## Windows での UI 確認

Windows、.NET 9 の MAUI 開発環境、Git 2.38.0 以降が必要です。初回はサブモジュールも取得します。

```powershell
git submodule update --init --recursive
dotnet build src/GameLauncherWithGit/GameLauncherWithGit.csproj -f net9.0-windows10.0.19041.0
dotnet run --project src/GameLauncherWithGit/GameLauncherWithGit.csproj -f net9.0-windows10.0.19041.0 --no-build
```

起動時には、その Windows ユーザーの登録済みリポジトリを監視・同期します。確認には既存データのない別の Windows ユーザープロファイルや仮想環境を使い、実際のセーブデータやリモートを登録しないでください。

「新規追加」でタイトルだけを入力して保存すると、リポジトリや実行ファイルを使わず一覧の表示を確認できます。環境設定、ゲーム編集、通知などを開き、必要な状態へスクロールしたうえで Windows の画面キャプチャ機能を使って撮影できます。共有前にパスや個人情報が画像に含まれていないことを確認してください。
