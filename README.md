# GameLauncherWithGit

## 開発・リリース運用

### 課題と対応予定

- 不具合、機能要求、対応が必要な後追いは [GitHub Issues](https://github.com/natumekazuki/GameLauncherWithGit/issues) で管理し、重複は既存の Issue に集約する。着手順は依頼内容と影響を踏まえ、データの安全性や主要な同期動作に関わるものを優先する。
- 正式版ごとに `vX.Y.Z` の Milestone を使い、対応予定が決まった Issue を割り当てる。Milestone 未指定は対応版未定のバックログとする。追加・延期するときは対象 Issue の割り当てと理由を更新する。
- 変更は作業ブランチで進め、`main` に統合する。対応した Issue は対象の変更が `main` に反映され、必要な確認が完了してから閉じる。重複や不採用の場合は理由を残して閉じる。Issue の完了と正式公開は別であり、Milestone は対象版の公開後、未完了課題の延期または対象外を整理して閉じる。
- リリース範囲を決めるときと公開前に、対象 Milestone の未完了課題と、Milestone 未指定でも今回の変更に関連する課題を確認する。未完了の非ブロッカーは公開判断と分け、延期する理由と引継ぎ先を Issue に残す。

### 互換性とデータ保護

実際に利用中の環境では、ゲーム登録・関連リポジトリ・セーブリンクの情報を含む `game-library.db`、`settings.json`、サムネイル、ゲームのセーブデータ、関連リポジトリのデータと同期先、および適用済みのデータ移行を維持対象とする。アプリ更新後も登録情報と設定を利用でき、セーブデータや同期先を損なわないようにする。必要な移行を行う場合も、既存データとその意味を維持する。

利用・適用済みかどうかで維持対象を判断し、Git タグの有無だけでは判断しない。未配布の開発途中の仕様や画面配置そのものとの互換性は保証しないが、そこで実際に使われているデータは保護する。データの消失や利用不能を伴う変更は、メジャーバージョンを上げるだけで実施せず、影響と対応方法を示して承認を得る。

### バージョン

正式版は `X.Y.Z` 形式とし、複数の種類の変更を含む場合は影響が最も大きいものに合わせる。

- `X`（メジャー）: 既存の動作環境、利用中の機能またはデータとの互換性を壊す変更。`Y` と `Z` を `0` に戻す。
- `Y`（マイナー）: 互換性を保つ機能追加や、機能・操作性の改善（不具合修正を除く）。`Z` を `0` に戻す。
- `Z`（パッチ）: 互換性を保つ不具合修正や、機能を追加しない内部改善・依存更新・文書変更。

番号の更新対象と Windows のビルド・MSIX 確認は、[バージョン更新チェックリスト](docs/design/windows-msix-keyvault-signing.md#7-バージョン更新チェックリスト)に従う。

### 正式公開

1. 公開範囲を決め、作業ブランチで対象版の番号を更新する。`docs/releases/vX.Y.Z.md` に変更内容、互換性への影響、実施した検証と未確認事項を記録する。詳細文書やソースへのリンクは、その版の内容に対応するコミットの完全ハッシュで固定する。
2. 公開対象の変更を `main` に統合し、対象コミットで必要なビルド・動作確認を行う。MSIX を配布する場合は配布用パッケージも確認する。確認結果が記録と異なれば公開前に記録を更新し、最終的な公開対象に確認結果が適用されることを確かめる。
3. 公開対象の `main` のコミットに `vX.Y.Z` タグを付け、同じタグを指定して GitHub Release を作成する。公開済みタグは移動・削除しない。同名タグのローカルとリモートが食い違う場合は強制更新せず、原因と対応を確認する。

方針の定義は、Issue や Milestone の更新、push、統合、タグ操作、公開の実行許可を代替しない。

### プレビュー公開

- 正式版に向けた確認用として、作業ブランチの確定コミットに `vX.Y.Z-preview.N`（`N` は1から増加）のタグを付け、同じタグで GitHub Release を Prerelease・非Latestとして公開する。プレビュー公開のための `main` 統合は行わず、正式公開時は上記の手順に従う。
- 番号更新、対象コミットと配布物の確認、`docs/releases/vX.Y.Z-preview.N.md` への変更・互換性・検証結果・未確認事項の記録は正式版と同じく必要。既知の制限と後追い Issue を明示し、未確認を確認済みとして扱わない。プレビューでも利用中のデータは保護する。
- アプリの表示番号は数値の `X.Y.Z`、サイドロード MSIX は `X.Y.Z.B` とし、`B` は `ApplicationVersion` に合わせる。各公開で `ApplicationVersion` を増やし、同じ `X.Y.Z` のプレビューから正式版へ移る際も末尾を `0` に戻さない。公開済みタグ・パッケージは差し替えず、修正は新しい番号で出す。
- MSIX とともに、サブモジュール・ネイティブ依存・ライセンス・ビルド手順を含む対応ソース一式を配布する。GitHub 自動生成のソースZIPだけではサブモジュールの内容を含まないため代用しない。公開操作には対象と範囲への明示承認が必要。

## Windows での UI 確認

Windows、.NET 9 の MAUI 開発環境、Git 2.38.0 以降が必要です。初回はサブモジュールも取得します。

シナリオ抽出のnative buildにはVisual Studio 2022のC++ x86/x64ツール、C++ ATL、Windows SDK、CMakeが必要です。スクリプトはATLを含むVisual Studioインスタンスを選び、32/64bitのHost・Hook・注入helperを構築します。初回はCMake依存取得にもネットワークを使います。

```powershell
git submodule update --init --recursive
./scripts/build-luna-native.ps1
dotnet build src/GameLauncherWithGit/GameLauncherWithGit.csproj -f net9.0-windows10.0.19041.0
$env:GAMELAUNCHER_DATA_DIRECTORY = Join-Path ([System.IO.Path]::GetTempPath()) ("GameLauncherWithGit-ui-" + [guid]::NewGuid().ToString("N"))
$env:WEBVIEW2_USER_DATA_FOLDER = Join-Path $env:GAMELAUNCHER_DATA_DIRECTORY "webview2"
dotnet run --project src/GameLauncherWithGit/GameLauncherWithGit.csproj -f net9.0-windows10.0.19041.0 --no-build
```

`GAMELAUNCHER_DATA_DIRECTORY` に絶対パスを指定すると、DB・設定・サムネイル・ログの保存先をそのディレクトリへ切り替えます。指定が不正な場合は起動に失敗し、通常の保存先へは戻りません。既存データのコピーや移行は行いません。上の例は毎回空の検証用ディレクトリを使い、WebView2 のデータも分離します。検証プロセスは設定したシェルから起動してください。このモードでは通常起動の単一起動制御を使わないため、同じ検証ディレクトリで複数起動しないでください。

未指定時は従来の保存先を使い、起動時に登録済みリポジトリを監視・同期します。検証用ディレクトリへ実データを持ち込まず、実際のセーブデータやリモートを登録しないでください。Windows の自動起動設定はプロファイル分離の対象外なので、検証中は変更しないでください。

「新規追加」でタイトルだけを入力して保存すると、リポジトリや実行ファイルを使わず一覧の表示を確認できます。環境設定、ゲーム編集、通知などを開き、必要な状態へスクロールしたうえで Windows の画面キャプチャ機能を使って撮影できます。共有前にパスや個人情報が画像に含まれていないことを確認してください。

## シナリオ抽出

ゲーム編集で次回起動からのON/OFFを設定します（初期値ON）。抽出設定の「画面から選択」を押して3秒以内にゲームを前面にするか、ウィンドウ・プロセスの検索で対象を選び、確認してテスト接続します。取得元ごとの直近の文章を比較し、本文・名前などの用途を指定します。名前の取得元から届く内容を話者に使うため、キャラクター名の事前登録は不要です。文章検索・表示の一時停止を使い、「判定」で分類と話者の仕上がりを確認できます。「確定して記録」で候補と本体パスをゲーム別に記憶し、その後の本文から保存します。テスト受信分は保存しません。接続後も選び直し・再試行できます。本のアイコンからシナリオ画面を開き、ゲーム単位の本文・分類・話者を閲覧・修正できます。分類はセリフ・地の文・未判定です。必要な時だけ、プレイ中の区間開始/終了アイコン、または本文の両端指定で自由な名前の区間を保存します。区間外の本文も残り、ゲーム全体/区間/分類で絞ったTXTを全件出力できます。登録削除後も履歴と区間は残ります。

保存履歴では名前・本文それぞれの部分一致と分類・区間を組み合わせ、すべての条件に一致する本文を閲覧・TXT出力できます。名前・本文は検索ボタンまたはEnterで適用し、空欄は条件にしません。本文を選んでゴミ箱を押すと、同じ受信原文から分割された本文も含めた削除内容を確認できます。「履歴管理」では区間の改名・削除と、抽出設定を残すゲーム単位の全履歴消去を行えます。区間だけを削除しても本文は残ります。本文・全履歴の削除は取得停止後に確定し、元に戻せません。

取得はベストエフォートで、OCR・翻訳・全作品対応・欠落救済は提供しません。信頼できるゲームだけへ接続してください。動作・データ・安全境界の詳細は[シナリオ抽出設計](docs/design/scenario-extraction.md)、依存と配布条件は[Third-party notices](THIRD-PARTY-NOTICES.md)を参照してください。

正式記録中はゲームを最前面にし、`Alt+Shift+S`でタイトルバーと枠を除いたスクリーンショットを保存できます。カメラの設定アイコンからキーと撮影ウィンドウを変更できます。Ctrlはゲームのスキップ操作と重なることがあるため、ゲームや他アプリで使わない組合せを選んでください。撮影対象は本文の取得先から自動選択し、別ウィンドウを選んでも本文の取得先は変わりません。画像は撮影時に最後に受け付けた本文へ紐づき、各本文の画像アイコンから確認できます。厳密な行同期ではなく、その付近のシーンとして利用します。

ZIPアイコンから、現在の区間・分類・名前・本文の条件に一致する全本文と関連画像を出力できます。ZIPには`manifest.json`、`texts.jsonl`、`images/`を含み、同じ画像は1ファイルにまとめます。画像はPNGで保存し、本文の削除時は他の本文から使われていない画像だけを削除します。ゲーム登録を削除しても履歴と画像は残ります。

保存処理と分類のtestは実ユーザーDBを使わず実行できます。

```powershell
dotnet test tests/GameLauncherWithGit.Capture.Tests
```

## 配布ソースからのビルド

Release に添付する `GameLauncherWithGit-vX.Y.Z[-preview.N]-source.zip` は、本体・`library/` のサブモジュール・`native/vendor/` の MinHook と uchardet を含むソース一式です。Git管理情報と秘密鍵は含みません。GitHub 自動生成のソースZIPとは異なります。

Windows の前提環境を用意して展開先で次を実行します。ネイティブ依存は同梱ソースを使い、NuGet と .NET workload の取得にはネットワークが必要です。

```powershell
./scripts/build-luna-native.ps1
dotnet build src/GameLauncherWithGit/GameLauncherWithGit.csproj -f net9.0-windows10.0.19041.0 -c Release
```

MSIX は `scripts/publish-windows-msix.ps1` で生成できます。署名とバージョンの扱いは [Windows 配布運用](docs/design/windows-msix-keyvault-signing.md)に従い、再配布には自身の署名証明書を使用してください。
